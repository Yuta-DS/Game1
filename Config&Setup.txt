RUN AS WEB: ./web   (rebuild: ./web rebuild | check it plays: ./web verify | stop: ./web stop)

WHAT ./setup.sh DOES (in order)

  1. Checks prerequisites are installed - python3, git-lfs, and Godot. dotnet
     is required only when this checkout contains a C# project. If one is
     missing it stops and prints the exact install command.
  2. git lfs pull, then verifies the LLM models are real binaries and not
     unpulled pointer stubs.
  3. Creates server/venv and installs the pinned Python dependencies.
  4. Builds the Godot import cache - the step missing from the original
     documentation, and the one that breaks the game if skipped. Takes a few
     minutes. See section 2.5 for why this matters.
  5. Builds the C# assembly only when a .csproj exists in artea/.

WHAT ./setup.sh run DOES

  Checks whether the server is already listening on port 8000. Starts it
  only if it is not, waits until it actually responds, then launches the
  game. Safe to run repeatedly.

BEFORE YOU RUN IT - install the prerequisites:

  macOS:   brew install git-lfs
           brew install --cask godot-mono
           brew install --cask dotnet-sdk

  Ubuntu:  sudo apt install -y git-lfs python3-venv python3-pip dotnet-sdk-8.0
           plus the Godot .NET build from godotengine.org

  Windows: run setup.sh from Git Bash with Python 3, Git LFS, Godot and
           .NET on PATH. Use GODOT_BIN if Godot is installed elsewhere.
           Section 5 has the manual setup and WSL alternatives.

The script searches /Applications, ~/Applications and PATH for Godot.
On Windows it also accepts executable names ending in .exe and the
virtual environment's Scripts/python.exe layout.

IF THE SCRIPT FAILS: it stops at the first problem and prints what to do.

===============================================================================
1. WHY macOS NEEDS DIFFERENT STEPS
===============================================================================

Four blockers, in the order you hit them:

  (a) PORT 80 IS PRIVILEGED
      server.py binds port 80. On Ubuntu the systemd unit runs as root so
      this succeeds. On macOS, running "python server.py" as a normal user
      fails to bind. Using sudo would work but runs the whole Flask app as
      root and leaves root-owned database.db and uploads/ behind.
      FIX: HOST/PORT are now environment variables. Use PORT=8000.

  (b) systemd DOES NOT EXIST ON macOS
      Every "sudo systemctl ..." command in the original docs has no macOS
      equivalent. flaskapp.service cannot be used.
      FIX: launchd LaunchAgent (section 2.6). Same outcome - starts at
      login, restarts on crash.

  (c) THE GODOT IMPORT CACHE IS NOT IN THE REPOSITORY
      This is the big one, and it is not macOS-specific - it affects any
      fresh clone on any OS. .godot/imported/ is a build artifact and is
      correctly gitignored. Until it is generated, EVERY asset fails to
      load, even though all the source files are present on disk.

      Symptom: the game boots to the start screen, you log in, and nothing
      happens. It looks exactly like a broken login. It is not - the login
      succeeds and the following scene load fails.

      FIX: run the import once (section 2.5). Required on every fresh clone.

  (d) THE PROJECT FILE NAME IN THE DOCS IS WRONG
      The docs say APIManager.gd. The actual file is:
          artea/scripts/API_Manager.gd        (note the underscore)
      It is autoloaded by UID, not by path:
          APIManager="*uid://dodj1s54vwit2"
      Searching the repository for "APIManager.gd" finds nothing.

2.9  AUTO-START THE SERVER AT LOGIN (launchd - the macOS systemd)
-------------------------------------------------------------------------------

Create ~/Library/LaunchAgents/com.artea.flaskserver.plist:

    <?xml version="1.0" encoding="UTF-8"?>
    <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
      "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
    <plist version="1.0">
    <dict>
        <key>Label</key>
        <string>com.artea.flaskserver</string>

        <key>ProgramArguments</key>
        <array>
            <string>/Users/YOU/S2603/server/venv/bin/python</string>
            <string>/Users/YOU/S2603/server/server.py</string>
        </array>

        <key>WorkingDirectory</key>
        <string>/Users/YOU/S2603/server</string>

        <key>EnvironmentVariables</key>
        <dict>
            <key>HOST</key>
            <string>127.0.0.1</string>
            <key>PORT</key>
            <string>8000</string>
        </dict>

        <key>RunAtLoad</key>
        <true/>

        <key>KeepAlive</key>
        <dict>
            <key>SuccessfulExit</key>
            <false/>
        </dict>

        <key>ThrottleInterval</key>
        <integer>10</integer>

        <key>StandardOutPath</key>
        <string>/Users/YOU/S2603/server/logs/flaskapp.out.log</string>

        <key>StandardErrorPath</key>
        <string>/Users/YOU/S2603/server/logs/flaskapp.err.log</string>
    </dict>
    </plist>

Replace /Users/YOU with your actual home directory. launchd does NOT expand
~ or environment variables in these paths - they must be absolute.

Then:

    mkdir -p ~/S2603/server/logs
    plutil -lint ~/Library/LaunchAgents/com.artea.flaskserver.plist
    launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.artea.flaskserver.plist

TWO DESIGN DECISIONS WORTH UNDERSTANDING:

  WorkingDirectory is mandatory. server.py opens database.db and uploads/
  by relative path. Without this key, launchd starts the process in / and
  the server silently creates a second, empty database somewhere else.

  KeepAlive uses SuccessfulExit=false, not a blanket true. A clean exit
  stays exited. Blanket true fights you every time you stop it deliberately.

Daily commands:

    # status
    launchctl print gui/$(id -u)/com.artea.flaskserver | grep -E "state|pid"

    # restart after editing server.py  <- the one you will use most
    launchctl kickstart -k gui/$(id -u)/com.artea.flaskserver

    # stop and disable auto-start
    launchctl bootout gui/$(id -u)/com.artea.flaskserver

    # start / re-enable
    launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.artea.flaskserver.plist

    # logs - Flask writes requests and tracebacks to stderr,
    # so .err.log is the one you want. .out.log stays near-empty.
    tail -f ~/S2603/server/logs/flaskapp.err.log

Verify auto-restart actually works (do not assume it):

    kill -9 <pid>
    sleep 12
    launchctl print gui/$(id -u)/com.artea.flaskserver | grep pid
    # PID should differ from the one you killed

    [Unit]
    Description=Flask Game Backend
    After=network.target

    [Service]

    WorkingDirectory=/home/ubuntu/server
    ExecStart=/home/ubuntu/server/venv/bin/python server.py

  1. It hardcodes /home/ubuntu/server. Deploying to any other path breaks

     means port 80 can no longer be bound directly - run on a high port with
     nginx in front, or grant CAP_NET_BIND_SERVICE.

6. SOURCE CHANGES MADE, AND WHY
===============================================================================

Every change is default-preserving. With no environment variables set,
server.py behaves exactly as it did before, so the Ubuntu deployment is
unaffected.

-------------------------------------------------------------------------------
6.1  server/server.py - HOST and PORT configurable  (THE macOS BLOCKER)
-------------------------------------------------------------------------------

BEFORE:
    app.run(
        host='0.0.0.0',
        port=80,
        debug=False
    )

AFTER (lines 324-327):
    app.run(
        host=os.environ.get('HOST', '0.0.0.0'),
        port=int(os.environ.get('PORT', 80)),
        debug=False
    )

Defaults unchanged, so systemd still gets 0.0.0.0:80.

-------------------------------------------------------------------------------
6.2  server/server.py - JWT secret from environment
-------------------------------------------------------------------------------

BEFORE:
    app.config['JWT_SECRET_KEY'] = 'dev_secret_change_later_12345'

AFTER (lines 30-33):
    app.config['JWT_SECRET_KEY'] = os.environ.get(
        "JWT_SECRET_KEY",
        'dev_secret_change_later_12345'
    )

The hardcoded literal stays as the fallback so nothing breaks. See section 8
- this secret being public is a real vulnerability, and the environment hook
is now in place, it just needs a value set in production.

-------------------------------------------------------------------------------
6.3  server/server.py - OpenRouter key from environment
-------------------------------------------------------------------------------

BEFORE:
    OPENROUTER_API_KEY = ""

AFTER (line 23):
    OPENROUTER_API_KEY = os.environ.get("OPENROUTER_API_KEY", "")

That empty string is where a live API key would be pasted, and a pasted key
gets committed. Reading from the environment keeps it out of the repository.
Behaviour with no key set is identical to before.

-------------------------------------------------------------------------------
6.4  server/server.py - Python 3.12+ deprecation
-------------------------------------------------------------------------------

BEFORE:
    timestamp = datetime.utcnow().strftime("%Y%m%d_%H%M%S")

AFTER (line 139):
    timestamp = datetime.now(timezone.utc).strftime("%Y%m%d_%H%M%S")

datetime.utcnow() is deprecated as of 3.12 and scheduled for removal. Same
output string. "timezone" added to the existing datetime import. Not
macOS-specific - affects any machine on Python 3.12+.

-------------------------------------------------------------------------------
6.5  artea/scripts/API_Manager.gd - server address
-------------------------------------------------------------------------------

Line 3:
    const BASE_URL = "http://54.252.162.122"      # before, production AWS
    const BASE_URL = "http://127.0.0.1:8000"      # after, local dev

REVERT THIS BEFORE DEPLOYING OR COMMITTING FOR THE TEAM.

-------------------------------------------------------------------------------
6.6  artea/start_screen.gd - fixed a broken connectivity check
-------------------------------------------------------------------------------

BEFORE:
    func check_internet_connection() -> bool:
        if IP.get_local_addresses().size() == 0:
            return false
        return true

This never returned false. IP.get_local_addresses() always includes the
loopback entries (127.0.0.1 / ::1) even with Wi-Fi switched off, so the list
is never empty. The "No internet connection! Use Guest Mode." message could
not fire, and the function did not do what its name claimed.

AFTER:
    func check_internet_connection() -> bool:
        if APIManager.BASE_URL.contains("127.0.0.1") or \
           APIManager.BASE_URL.contains("localhost"):
            return true

        for address in IP.get_local_addresses():
            if address.begins_with("127.") or address == "::1":
                continue
            if address.begins_with("169.254.") or \
               address.to_lower().begins_with("fe80"):
                continue
            return true

        return false

Skips loopback and link-local (169.254.x / fe80: - APIPA self-assigned
addresses, which mean no usable route). Short-circuits to true when BASE_URL
is localhost, because otherwise it would block login against a local
development server, which is the setup this whole document describes.

    ls artea/.godot/imported/ | wc -l

-------------------------------------------------------------------------------
PROBLEM: Thousands of "Failed loading resource" / "Parse Error" lines
-------------------------------------------------------------------------------

Same cause as above - empty import cache. Note this also produces
Firebase addon parse errors such as:

    Parse Error: Could not find type "FirebaseDatabaseReference"

These look like a Godot version incompatibility but are not. They disappear
once the import cache is built.

-------------------------------------------------------------------------------
PROBLEM: Permission denied binding port 80
-------------------------------------------------------------------------------

Expected on macOS. Use PORT=8000. Do not use sudo - it leaves root-owned
database.db and uploads/ files that your normal user cannot then write to.

-------------------------------------------------------------------------------
PROBLEM: "Address already in use" on port 8000
-------------------------------------------------------------------------------

Usually the launchd agent already has it.

    lsof -nP -iTCP:8000 -sTCP:LISTEN
    launchctl bootout gui/$(id -u)/com.artea.flaskserver     # stop it
    # then run manually

-------------------------------------------------------------------------------
PROBLEM: git lfs pull leaves small files / "version https://git-lfs..."
-------------------------------------------------------------------------------

The files are pointer stubs, not real binaries.

    brew install git-lfs
    git lfs install
    git lfs pull

Verify with the head -c 4 check in section 2.2.

-------------------------------------------------------------------------------
PROBLEM: launchd agent will not start
-------------------------------------------------------------------------------

    plutil -lint ~/Library/LaunchAgents/com.artea.flaskserver.plist
    launchctl print gui/$(id -u)/com.artea.flaskserver
    tail -20 ~/S2603/server/logs/flaskapp.err.log

Most common cause: a path in the plist is not absolute, or contains ~ or an
environment variable. launchd does not expand either.

PROBLEM: dotnet build fails on net8.0 target
-------------------------------------------------------------------------------

The .NET 10 SDK builds net8.0 fine. If it genuinely fails:

    dotnet --list-sdks
    brew install --cask dotnet-sdk

It does not exist under that name. The file is:

    artea/scripts/API_Manager.gd

-------------------------------------------------------------------------------
8.1  SECURITY - raise these with the team before the next deploy
-------------------------------------------------------------------------------

  1. DEFAULT JWT SECRET IS PUBLIC.
     'dev_secret_change_later_12345' is in the repository. Anyone who can
     read the repo can forge a valid token for any user id and access that
     user's artworks. The signing key is the only thing between an attacker
     and a token that says "I am user 1".
     FIX: set JWT_SECRET_KEY in the systemd unit. The hook exists (6.2), it
     just needs a value.

  2. flaskapp.service RUNS AS User=root.
     Any RCE bug in Flask gives up the whole machine. See section 4.

  3. THE FLASK DEVELOPMENT SERVER IS SERVING PRODUCTION.
     Its own startup banner says not to. Single-threaded, no hardening.
     Use gunicorn or waitress.

  4. NO UPLOAD SIZE LIMIT.
     A client can POST an arbitrarily large body to /upload_artwork and fill
     the disk. Flask's MAX_CONTENT_LENGTH is the standard fix.
